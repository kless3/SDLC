2 КРАТКИЕ ТЕОРЕТИЧЕСКИЕ СВЕДЕНИЯ

2.1 Интегрированная среда разработки и её компоненты

Интегрированная среда разработки объединяет редактор исходного кода, средства навигации и рефакторинга, систему сборки, запуск приложения, отладчик, средства тестирования, терминал, интеграцию с системой контроля версий и расширения. IntelliJ IDEA анализирует Java-код во время редактирования, показывает ошибки и предупреждения, предлагает быстрые исправления и позволяет запускать класс с методом main непосредственно из редактора.

2.2 Редактирование и навигация в IntelliJ IDEA

Редактор IntelliJ IDEA поддерживает автодополнение, автоматический импорт классов, форматирование, безопасное переименование и поиск использований. Для перехода к объявлению используется Ctrl+B, для поиска использований – Alt+F7, для форматирования – Ctrl+Alt+L, а для вызова быстрых исправлений – Alt+Enter. Структура проекта отображается в окне Project, сообщения компилятора и программы – в окнах Build и Run.

2.3 Сборка, запуск и отладка Java-приложения

Исходные файлы компилируются компилятором javac в байт-код виртуальной машины Java. В IntelliJ IDEA проект собирается командой Build Project, а запуск класса App выполняется командами Run или Debug. Точку останова можно установить щелчком в поле слева от строки либо сочетанием Ctrl+F8. Во время остановки окно Debug показывает стек вызовов, текущую строку и значения переменных. Команды Step Over, Step Into и Step Out позволяют выполнять программу пошагово.

2.4 Паттерн MVC

MVC делит приложение на три взаимодействующие части. Модель хранит состояние и выполняет предметную логику. Представление создаёт пользовательский интерфейс и показывает результат. Контроллер принимает действия пользователя и вызывает необходимые операции модели. Благодаря такому разделению справочник продуктов и проверку данных можно тестировать отдельно от Swing-интерфейса.

2.5 Активная и пассивная модель

При пассивной модели контроллер после изменения данных сам получает новое состояние и передаёт его представлению. Активная модель самостоятельно уведомляет подписчиков об изменениях. В разработанном приложении GlycemicIndexModel использует PropertyChangeSupport, а MainView реализует PropertyChangeListener. После успешного поиска продукта модель публикует событие, и главное окно автоматически отображает новое состояние.

2.6 Гликемический индекс

Гликемический индекс (ГИ) показывает, насколько быстро углеводы из продукта повышают уровень глюкозы в крови по сравнению с чистой глюкозой. В приложении используется распространённая учебная классификация: низкий ГИ – до 55 включительно, средний – от 56 до 69, высокий – от 70. Значение может различаться в зависимости от сорта продукта, состава и способа приготовления, поэтому встроенный справочник имеет демонстрационный характер и не заменяет медицинскую рекомендацию.

Источник: International Tables of Glycemic Index and Glycemic Load Values 2021, American Journal of Clinical Nutrition:
https://ajcn.nutrition.org/article/S0002-9165(22)00494-4/fulltext



3 ОПИСАНИЕ ВЫПОЛНЕННОГО ВАРИАНТА ЗАДАНИЯ

3.1 Постановка задачи

Разработана программа «Гликемический индекс продуктов». На главной форме приведено определение понятия «гликемический индекс» и размещена кнопка «Ввести продукт». После нажатия кнопки открывается модальное окно с текстовым полем. Пользователь вводит название, а программа проверяет данные, выполняет поиск во встроенном справочнике и отображает на главной форме каноническое название продукта, значение ГИ и категорию: низкий, средний или высокий.

Последний корректно найденный продукт хранится в модели и показывается на главной форме. При повторном открытии окна ввода его название восстанавливается в текстовом поле. Если строка пустая, слишком короткая, слишком длинная, содержит недопустимые символы или продукт отсутствует в справочнике, появляется диалог с сообщением об ошибке. Некорректная попытка не заменяет последние корректные данные.

3.2 Настройка среды и расширений для UML и SysML v2

В IntelliJ IDEA открывается отдельный Maven-проект glycemic-index с каталогом src/main/java и корневым пакетом by.bsuir.glycemicindex. В качестве Project SDK выбран JDK 25. Класс by.bsuir.glycemicindex.App содержит метод main и используется в конфигурации запуска. Графический интерфейс построен на стандартной библиотеке Java Swing, внешние библиотеки для работы приложения не требуются.

Для UML используется файл docs/mvc.puml, совместимый с PlantUML Integration. В диаграмме показаны все объявленные поля классов, а названия сущностей, типов и связей приведены на английском языке. Структурное описание системы в нотации SysML v2 находится в файле docs/architecture.sysml.

3.3 Демонстрация отладчика

Работа отладчика демонстрируется в методе updateState класса GlycemicIndexModel. Точка останова устанавливается на строке вызова changeSupport.firePropertyChange(). В окне Debug можно проследить значения oldState и newState, проверить сохранение введённого продукта и увидеть момент отправки события представлению.

Дополнительную точку останова можно поставить в методе findProduct. Переменная normalizedName содержит проверенную и очищенную строку, а product – найденную запись ProductInfo. Так можно пошагово проверить нормализацию регистра, поиск значения ГИ и определение категории продукта.

3.4 Структура проекта и каркас MVC с активной моделью

Проект разделён на следующие компоненты:
– GlycemicIndexModel – проверяет название, выполняет поиск во встроенном справочнике, хранит состояние и уведомляет подписчиков;
– GlycemicState – представляет неизменяемый снимок текущего состояния;
– ProductInput – хранит последнее корректное название продукта;
– ProductInfo – содержит отображаемое название, значение ГИ и категорию;
– GlycemicCategory – перечисляет категории LOW, MEDIUM и HIGH;
– MainView – отображает определение, последний продукт и результат, а также принимает события активной модели;
– InputDialog – представляет модальное окно ввода продукта;
– GlycemicIndexController – обрабатывает действия пользователя и передаёт данные модели;
– ValidationException – описывает ошибки проверки входных данных;
– App – создаёт компоненты MVC и запускает приложение в потоке обработки событий Swing.

GlycemicIndexModel является активной моделью. После успешного поиска метод updateState заменяет снимок состояния и вызывает firePropertyChange. Объект MainView получает GlycemicState в методе propertyChange и обновляет элементы формы. Контроллер не передаёт результат представлению вручную.

3.5 Модель

Класс GlycemicIndexModel содержит встроенный неизменяемый справочник продуктов и объект GlycemicState. Поиск выполняется методом findProduct. Перед обращением к справочнику метод validateAndNormalize удаляет пробелы по краям, заменяет повторяющиеся пробелы одним и проверяет длину строки. Допускаются только буквы, пробелы и дефис. Для поиска строка переводится в нижний регистр, а буква «ё» приравнивается к «е».

Если продукт найден, создаётся ProductInput с каноническим названием и используется соответствующий ProductInfo. Категория формируется по значению индекса: до 55 – низкий, 56–69 – средний, от 70 – высокий. После этого модель публикует новое состояние. В справочнике предусмотрены распространённые продукты и несколько понятных синонимов, например «макароны» и «спагетти», «мёд» и «мед».

3.6 Представление

Представление состоит из классов MainView и InputDialog. Главное окно MainView содержит определение гликемического индекса, области «Последние введённые данные» и «Результат», а также кнопку «Ввести продукт». Текстовые области недоступны для редактирования и поддерживают перенос строк.

InputDialog содержит JTextField, кнопку «Найти» и кнопку «Отмена». Нажатие Enter в текстовом поле выполняет тот же обработчик, что и кнопка «Найти», а Escape закрывает окно. При повторном открытии конструктору передаётся объект ProductInput, и метод restore восстанавливает последнее корректное название.

MainView реализует PropertyChangeListener. Метод propertyChange получает новый GlycemicState и вызывает render. Если уведомление поступило не из потока обработки событий Swing, обновление интерфейса переносится в этот поток с помощью SwingUtilities.invokeLater.

3.7 Контроллер

Класс GlycemicIndexController связывает действия пользователя с моделью и представлением. Метод start подписывает MainView на события модели, назначает обработчик кнопки, отображает начальное состояние и открывает главную форму. Метод openInputDialog получает последние данные из модели и создаёт окно ввода.

После нажатия кнопки «Найти» контроллер передаёт строку методу model.findProduct. При успешном поиске модель уведомляет представление, а окно ввода закрывается. Контроллер перехватывает ValidationException и передаёт её сообщение методу showError. Представление показывает ошибку через JOptionPane.

3.8 Запоминание данных и обработка ошибок

Последний корректный ввод хранится внутри GlycemicState. Перед открытием InputDialog контроллер вызывает model.getLastInput() и передаёт результат диалогу. Данные обновляются только после успешной проверки и нахождения продукта, поэтому любая ошибка оставляет прежнее состояние без изменений.

Обрабатываются следующие случаи:
– строка отсутствует или состоит из пробелов;
– название короче 2 или длиннее 60 символов;
– введены цифры, специальные символы или другие недопустимые знаки;
– корректно оформленного продукта нет во встроенном справочнике.

Во всех случаях создаётся ValidationException с понятным текстом. Пользователь может исправить значение в том же окне и повторить поиск.

5 ОТВЕТЫ НА КОНТРОЛЬНЫЕ ВОПРОСЫ

Вопрос 1 Какие компоненты входят в состав IDE?

Основные компоненты IDE:
– редактор кода;
– средства сборки проекта;
– средства запуска проекта;
– средства отладки;
– средства тестирования;
– поддержка совместной работы;
– расширения.

Вопрос 2 Каковы основные приёмы работы с редактором кода?

К основным приёмам относятся автодополнение, быстрые исправления, автоматический импорт, форматирование, переход к объявлению, поиск использований, переименование, просмотр иерархии классов и анализ предупреждений. Эти операции ускоряют изменение кода и уменьшают вероятность механических ошибок.

Вопрос 3 Каким образом выполняется сборка и запуск проекта?

Во время сборки компилятор javac преобразует файлы Java в байт-код JVM – файлы с расширением .class. В IntelliJ IDEA сборка выполняется командой Build Project. Для запуска выбирается класс App с методом public static void main(String[] args), после чего выполняется команда Run. Проект также можно собрать Maven-командой mvn package при выбранном JDK 25 либо компилятором javac --release 25 и запустить класс by.bsuir.glycemicindex.App.

Вопрос 4 Что такое MVC?

MVC – архитектурный паттерн, разделяющий приложение на три части. Model хранит данные и выполняет основную логику. View отображает информацию и элементы графического интерфейса. Controller обрабатывает действия пользователя и передаёт команды модели. В данной работе роль модели выполняет GlycemicIndexModel, роль представления – MainView и InputDialog, а роль контроллера – GlycemicIndexController.

Вопрос 5 Чем отличается активная модель от пассивной?

Пассивная модель не уведомляет представление, поэтому после её изменения контроллер должен отдельно обновить интерфейс. Активная модель публикует событие при изменении своего состояния. В приложении GlycemicIndexModel вызывает firePropertyChange, а MainView получает новое состояние через метод propertyChange и самостоятельно обновляет элементы формы.

App.java

package by.bsuir.glycemicindex;

import by.bsuir.glycemicindex.controller.GlycemicIndexController;
import by.bsuir.glycemicindex.model.GlycemicIndexModel;
import by.bsuir.glycemicindex.view.MainView;
import javax.swing.SwingUtilities;

public final class App {
    private App() {
    }

    public static void main(String[] args) {
        SwingUtilities.invokeLater(() -> {
            GlycemicIndexModel model = new GlycemicIndexModel();
            MainView view = new MainView();
            GlycemicIndexController controller =
                    new GlycemicIndexController(model, view);
            controller.start();
        });
    }
}

GlycemicIndexModel.java – изменение состояния активной модели

private void updateState(GlycemicState newState) {
    GlycemicState oldState = state;
    state = newState;
    changeSupport.firePropertyChange(STATE_PROPERTY, oldState, newState);
}

MainView.java – получение события модели

@Override
public void propertyChange(PropertyChangeEvent event) {
    if (!GlycemicIndexModel.STATE_PROPERTY.equals(event.getPropertyName())) {
        return;
    }

    GlycemicState newState = (GlycemicState) event.getNewValue();
    if (SwingUtilities.isEventDispatchThread()) {
        render(newState);
    } else {
        SwingUtilities.invokeLater(() -> render(newState));
    }
}

GlycemicIndexController.java – передача ввода модели и обработка ошибки

dialog.onSubmit(() -> {
    try {
        model.findProduct(dialog.getProductName());
        dialog.close();
    } catch (ValidationException exception) {
        view.showError(dialog, exception.getMessage());
    }
});
